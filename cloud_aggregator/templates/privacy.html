Privacy & Security at the Edge

Keeping raw sensor data on the device is the first privacy layer. Differential privacy (DP) adds a second, mathematical one for the model updates themselves. This page is honest about how much each one buys — and what this demo does not protect.

2 · Threat model

ThreatIn this project
Server reads raw vibration dataPrevented — only decisions & weights leave the node
Model update leaks training dataMitigated only with DP (below); plain FedAvg does not stop it
Tampered / wrong model on a nodeDetected — SHA-256 of the running model is in every message
Eavesdropping on MQTTNot protected — demo broker is plaintext, anonymous
Fake nodes / forged commandsNot protected — no authentication on MQTT or the command API
Malicious client poisons FedAvgNot protected — no robust aggregation / secure aggregation
Production fix list: TLS + client certificates on MQTT, broker ACLs per topic, signed model updates, secure aggregation.

Results

Read these numbers with care. The bundled DP sweep is deliberately short (6 rounds, 1 seed) so it can be regenerated quickly, and with small client shards training is still unstable at round 6 — so the curve is noisy and not always monotonic (for example a clip-only run can land below a noisier one). Treat it as the shape of the trade-off, not as precise values. For a proper study run python federated/compare_dp.py --seeds 0 1 2 --clients 3 12 24 --rounds 15.
