About EdgeSentry

EdgeSentry detects bearing faults (normal · inner-race · outer-race · ball) on the machine itself, with a compressed model trained collaboratively across machines by federated learning — no raw sensor data leaves a device.

Architecture

Edge-computing features built in

  • On-device inference with an INT8 TFLite model — the decision never needs the cloud
  • On-device debounced alarm that keeps working with the uplink cut
  • Store-and-forward: bounded buffer, backlog flushed on reconnect
  • Report-on-change + heartbeat to save bandwidth and energy
  • Model hot-swap (full ↔ pruned) from the dashboard, with SHA-256 integrity
  • Edge orchestration: control channel from cloud to edge over MQTT
  • Condition-monitoring features (kurtosis, crest factor) computed on-device
  • Uncertainty flag for low-confidence windows (possible novel faults)
  • Sensor-noise injection to study degradation live
  • Resource limits in Docker (0.5 CPU, 256 MB) to mimic a small device
  • Real-time check: latency vs. the 21 ms window budget
  • Edge-fit calculator for MCU/SBC flash & RAM budgets

Model & data

1-D CNN: 3 conv blocks (16/32/64 filters, BatchNorm) → global average pooling → dense 32 → softmax(4). 11 972 parameters, ≈ 0.98 M MACs per window, 27.8 KB as INT8.

Data: real CWRU Bearing Data Center drive-end recordings at 48 kHz, 1 hp load. Each of the 3 machines holds one defect size (0.007 / 0.014 / 0.021 in) → naturally non-IID. Windows are 1024 samples, per-window z-normalised.

Leak-free split: each recording is cut in time — the first 70% yields training windows (50% overlap), the last 30% yields test windows (no overlap), with a gap. No test sample appears in any training window.

Honest limitations

  • Federated training is simulated in one process. The data flow follows the FL protocol, but nodes do not train over the network. Only inference and monitoring run as separate edge nodes over MQTT.
  • No real edge hardware was used. Latency is measured on a laptop/server CPU; peak-RAM and MCU time are analytic estimates.
  • One lab, one load condition, 3 defect sizes. Accuracy on a new defect size is much lower (see Federated Learning page). Real machines add speed/load variation and noise.
  • Noise sensitivity: trained on clean data; accuracy falls steeply at low SNR.
  • FedAvg trails pooled training because of non-IID client drift; DP only gives a meaningful guarantee with far more clients.
  • Edge nodes replay held-out test windows as a stand-in for an accelerometer; the broker is plaintext and unauthenticated.
