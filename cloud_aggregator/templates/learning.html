Federated Learning

Three machines each hold vibration data from a different defect size and may not share it. Each trains locally and sends only model weights; a server averages them (FedAvg). Below: what that buys over training alone, what it costs versus pooling all the data, and where it still falls short.

Does it work on a machine it has never seen?

Leave-one-severity-out: train on two machines, test on the third (a defect size never seen in training). This is a harder, more realistic question than the standard split.

The server's whole job, for a single weight. Change the numbers and watch the average move — each machine's vote is weighted by how much data it has.


Why the FedAvg gap? Each node trains to near-perfection on its own defect size, so the local updates pull in different directions ("client drift"). Averaging them gives a model that is good for everyone but optimal for no one. We tried lower learning rates, fewer local epochs, a different normalisation layer and learning-rate decay: decay stabilises convergence, none of them closes the gap — it is a property of this non-IID split.
